## 1. 측정된 격차 — 이게 이번 재설계의 출발점

문서 2절: **전근대사 : 근·현대사 출제 비중 = 60 : 40**

현재 앱 상태(실측):

| 구분 | 전근대 | 근현대 | 현재 비율 | 목표 |
| --- | --- | --- | --- | --- |
| 학습일 | 20일 | 8일 | **71 : 29** | 60 : 40 |
| 카드 | 1,390 | 562 | 71 : 29 | 60 : 40 |
| 퀴즈 | 846 | 336 | 72 : 28 | 60 : 40 |

전근대가 약 11%p 과대, 근현대가 그만큼 과소하다. 28일 기준 **전근대 17일 / 근현대 11일**이 목표치다.

(전근대 = prehistory ~ late-joseon / 근현대 = open-port, colonial, modern)

### 1-1. 남의 요약치 대신 직접 측정한 값 (2026-07-30 추가)

`scripts/gen-exam-frequency.ts` 로 시험 자료실이 공개 중인 **심화 22개 회차(57~78회) 1,093문항**을
직접 내려받아 문항별로 시대를 분류했다 → `src/data/exam-distribution.ts` (자동 생성).

| 구분 | 실측 | 흔히 인용되는 추정 |
| --- | --- | --- |
| 전근대 : 근현대 | **58.5 : 41.5** (639 : 454문항) | 60 : 40 |
| 선사·고대 | 19.5% (213문항) | 10~15% |
| 고려(후삼국 포함) | 18.4% (201문항) | 14~15% |
| 조선 | 20.6% (225문항) | 20~25% |
| 근대·일제 | 29.1% (318문항) | 25~31% |
| 현대 | 12.4% (136문항) | 12~14% |

- 헤드라인 60:40 은 실측 58.5:41.5 로 사실상 확인됐다 → **§3 의 17일 / 11일 배분은 그대로 유효**하다.
- 다만 추정치의 하위 구간은 다 더해도 전근대 55% 를 못 넘어 앞뒤가 맞지 않았다. 실측에서는
  **선사·고대와 고려가 추정보다 4~5%p 높다**. 감량 대상을 고를 때 이 쪽을 과도하게 깎지 않는다.
- 단계별 실측 비중은 커리큘럼 화면의 접이식 패널(`src/components/ExamShareSummary.tsx`)에서
  학습일 배분과 나란히 볼 수 있다.

### 1-2. 기출 개념 인벤토리 — 다음 단계의 콘텐츠 범위 (2026-07-30 추가)

출제 비중(§1-1)은 "어느 시대를 몇 일 배울지"를 정해 주지만 "무엇을 카드로 만들지"는 정해 주지
않는다. 그래서 22회차 선택지에서 개념을 직접 뽑아 목록으로 만들었다 →
`src/data/exam-topics.ts`(자동 생성) · 격차 분석 `docs/exam-topic-gap-2026-07-30.md`.

- 정답 선택지만 세지 않는다. 한능검 선택지는 정답이든 오답이든 **그 자체로는 모두 사실인 문장**이고
  제시문 키워드와 맞는 것을 고르는 시험이므로, 오답 선택지도 출제된 개념 한 개다.
  → 선택지 4,699개에서 개념 **1,958개**(등장 3회 이상).
- 그중 대응 카드가 **있는 개념 936개(47.8%)** · **없는 개념 1,022개(52.2%)**.
  반대로 인벤토리 개념이 하나도 걸리지 않는 기존 카드가 **1,064/1,952장**(그중 귀속 0회 876장).
- **Day 단위 작업(§7)의 카드/퀴즈 범위는 이 인벤토리를 1차 기준으로 삼는다.** 추가는 격차 문서 §2,
  감량 1차 후보는 §3 을 본다. 다만 선택지는 사건명을 쓰지 않고 서술로 표현하는 일이 많아
  (예: '병인양요'는 선택지에 직접 2회만 등장) **인벤토리에 없다고 시험에 안 나오는 개념이 아니다** —
  교과서 핵심 개념은 인벤토리에 없어도 유지한다.

## 2. 변경 원칙

문서 6절(수칙)·7절(빈출 팁)·8절(특수한 파트)에서 도출한다.

1. **줄인다 (6.1)** — 절대평가 80점이 목표이므로 "50문제 중 2문제 미만" 주제는 버린다.
   판단 근거는 감이 아니라 `src/data/exam-frequency.ts`(심화 기출 22회차 **선택지 전체** 실측 —
   2026-07-30 재집계. 한능검 선택지는 정답이든 오답이든 그 자체로 사실인 문장이므로 오답도
   출제된 개념 한 개로 센다. 정답/오답 횟수는 분리 보관)를 쓴다.
   빈출 0회 + 교과서 핵심도 아닌 카드가 감량 1순위.
2. **연계한다 (6.2)** — 단일 사건을 따로 외우게 하지 않고, 키워드에서 가지를 뻗게 만든다.
   → 신규 카드 유형 3종(§4)의 근거.
3. **사진을 지킨다 (8.1)** — 문화재(탑·불상·건축물·그림·도자기)는 사진 없이 학습이 불가하다.
4. **순서를 외우게 한다 (8.2)** — 연표형 문제는 인과관계로 묶어 제시한다.
5. **매회 나오는 파트를 비운 채 두지 않는다 (8.3)** — 세시풍속·전통놀이는 거의 매회 1문제.

## 3. 커리큘럼 재배분 (28일 유지)

- 전근대 20일 → **17일**: 빈출 낮은 단원을 통합해 3일 확보.
- 근현대 8일 → **11일**: 개항기·일제강점기·현대에 3일 배분.
- `DAY_PLAN`(`src/data/curriculum.ts`)의 `units` 묶음을 재구성한다. **단원 번호(1~90)는 유지**한다 —
  카드/퀴즈 id(`dNN-cNN`)와 오디오 파일명, `IMAGE_OVERRIDES`, 즐겨찾기가 모두 이 번호에 묶여 있다.
  즉 **재배분은 "어느 단원을 몇 일차에 배치할지"만 바꾸고 단원 자체는 유지**한다.
- `daySlug`는 일차 제목 기반이라 제목이 바뀌면 URL이 바뀐다. 기존 슬러그는
  `day-slug.ts`의 하위호환 맵에 남겨 색인된 URL이 깨지지 않게 한다.

## 4. 신규 카드 유형 3종

기존 `StudyCard`를 그대로 쓰고 제목 접두사로 구분한다(스키마 변경 없음).

### 4-1. 지역 연계 카드 — "시험마다 한 문제는 꼭 나온다"(6.2 예시 2)
한 지역에서 일어난 사건을 시대를 넘어 한 장에 모은다.
대상: 강화도, 평양, 제주도, 공주, 의주, 원산, 충주, 안동, 익산, 부여, 수원, 김해, 양산, 강릉.

### 4-2. 인물 연계 카드 (6.2 예시 3)
한 인물의 소속 단체·사건을 한 장에 모은다. 예: 김구 → 한인애국단·상해 임시정부·한국독립당·남북협상.

### 4-3. 연표/순서 카드 (8.2)
문서가 제시하는 인과 묶음을 그대로 학습 단위로 만든다.
- 신라의 삼국 통일: 살수대첩 → 안시성 → 나당동맹 → 황산벌 → 백제 멸망 → 백제부흥 → 백강 → 고구려 멸망 → 고구려부흥 → 매소성/기벌포 → 통일
- 후삼국 통일: 고려 건국 → 발해 멸망 → 공산 → 고창 → 견훤 유폐 → 신라 항복 → 일리천
- 조선 정치: 사화 → 예송 → 환국
- 임진왜란 / 정유재란 / 정묘·병자호란
- 외세 침입: 병인박해 → 셔먼호 → 병인양요 → 오페르트 → 신미양요 → 척화비 → **운요호**(척화비 이후)
- 근대 조약: 강화도 → 조일수호조규 → 조미수호통상 → 임오군란 → 제물포/조청상민 → 조일통상장정

순서 배열 퀴즈를 함께 만든다.

## 6. 문화재 사진 정책 — 직전 작업과의 충돌 해소

2026-07-30 이미지 검토에서 사진 107건을 제거했다. 그런데 8.1은 **문화재는 사진 없이 학습 불가**라고 한다.
두 판단이 충돌하는 항목만 되살린다.

- **되살릴 대상**: 탑·불상·건축물·그림·도자기 등 "모양을 몰라 틀릴 수 있는" 문화재.
  예) `d43-c06` 부석사 무량수전, `d43-c07` 수덕사 대웅전.
- **제거 유지**: 인물 초상, 유적지 원경, 지도, 문서 사진 등 모양 자체가 출제되지 않는 것.
  (`d50-c07` 이황, `d11-c03` 풍납토성, `d32-c23` 5도 양계 지도 등)

Day 단위 작업 중 해당 일차에 문화재 카드가 있으면 이 기준으로 재판정한다.

## 7. 실행 방식 — Day 단위

설계(이 문서) 확정 후 **Day 1 → Day 28 순서로** 진행한다. 각 Day마다:

1. 그 일차의 단원 카드/퀴즈를 §2 원칙으로 감량·보강 (`src/data/content/days-*.ts`)
2. 필요하면 §4 신규 카드 추가, §6 기준으로 사진 재판정
3. `npm run validate:content` → `npx tsc --noEmit` → `npm run lint`
4. 변경된 카드의 음성 재생성 (§8)
5. 커밋 1개 (`Day N 콘텐츠 재설계`) → push

커리큘럼 재배분(§3)은 Day 작업 **이전에** 한 번에 수행한다 — 일차별 단원 구성이 먼저 정해져야
Day 단위 작업의 대상이 확정된다.

## 8. 음성(TTS) 재생성

- 파이프라인: `scripts/gen-audio.ts` → `edge-tts`(무료·로컬, API 키 불필요),
  보이스 `ko-KR-SunHiNeural`, rate `-8%` → `public/audio/cards/<카드id>.mp3` + `src/data/audio-manifest.ts`
- 2026-07-31 전량 재생성 완료 (`FORCE=1` 로 전 단원). 이후 단원 5·6 감량·통합을 반영해
  현재 mp3 **1,885개 = 카드 수와 동일** — 이 등식이 유지되는지가 점검 기준이다.
- `edge-tts` 는 `.venv-tts`(gitignore)에 설치돼 있다: `EDGE_TTS=./.venv-tts/bin/edge-tts`.
- 음성을 다시 만들면 **예상 소요시간 근거도 함께 갱신**한다(`npm run gen:day-time`).
- 카드 **내용이 바뀌면 반드시 재생성**한다(낭독 텍스트가 카드 본문이므로).
  카드를 삭제하면 해당 mp3와 매니페스트 엔트리도 정리한다.
- 스크립트는 기존 파일을 건너뛰므로, 내용이 바뀐 카드만 `FORCE=1`로 개별 재생성한다.

## 10. 선사 단원 통합 (2026-07-31) — §9 의 예외

Day 1 감량으로 단원 1~4 의 카드가 5·6·9·3장까지 줄어, 단원 하나에 카드 3장짜리 구성이 남았다.
그래서 **단원 1~4 를 단원 1 "선사 시대의 생활" 하나로 통합**했다(카드 23장 / 퀴즈 55문항).
단원 총수는 90 → **87**이며 남은 단원 번호(5~90)는 건드리지 않았다 — 즉 단원 번호는
연속이 아니다(1 · 5~90). 번호 범위를 훑는 코드는 `TOTAL_UNITS` 대신 `UNIT_NUMBERS` 를 쓴다.
(§11 에서 단원 6 이 5 로 통합되어 현재 번호는 1 · 5 · 7~90 이다.)

§9 가 번호 변경을 금지한 이유는 id 에 묶인 데이터를 지키기 위함이므로, 통합 대신 **묶여 있는
것들을 전부 함께 이관**했다.

| 묶여 있던 것 | 처리 |
| --- | --- |
| 카드/퀴즈 id | `d01-c01…c23` / `d01-q01…q55` 로 시대 순서 그대로 재번호 |
| `public/audio/cards/*.mp3` | 살아 있는 11개 `git mv` (3개는 id 동일) · 나머지는 재생성 |
| `IMAGE_OVERRIDES` · `IMAGE_ALIASES` | 키와 alias 대상 모두 이관(11건), 카드가 사라진 3건 제거 |
| `images.ts`(자동 생성) | 키 이관 23건 · 죽은 키 6건 제거. **생성물이라도 그냥 두면 안 된다** — 새 id 가 옛 죽은 키(예: 옛 `d01-c12` 연천 전곡리)와 충돌해 엉뚱한 사진이 붙을 수 있고, 이관하지 않으면 유물 사진 15장이 조용히 사라진다 |
| `exam-frequency` · `exam-topics` · `exam-distribution` | 손으로 고치지 않고 `npm run gen:exam -- --emit` 로 재생성 |
| 즐겨찾기(`favoriteCards`/`favoriteQuizzes`) | **이관 불가**(localStorage·Supabase 에 생 id 저장). 옛 `d02/d03/d04-*` 즐겨찾기는 유실된다 |

시대 구분(`ERAS`)도 구석기·신석기·청동기·철기 4개를 **'선사' 하나로 합쳤다**. 시대 라벨은 단원
